## Issue 1: DbConnector.connect() resolves with undefined instead of rejecting on connection-refused (mysql, postgres, neo4j)

### Summary
All three `connect()` implementations resolve with `undefined` instead of rejecting with a `DbConnectorError(code=DB_CONNECTION_FAILED, phase=connect, engine=<x>)` when the target port is refused. This is a contract violation — every consumer expects a rejection on unreachable hosts.

### Reproduction
Tests are skipped with TODO(v1.0.3) tags in:
- `tests/integration/db/real-driver/mysql.real.integration.test.ts` — line 407
- `tests/integration/db/real-driver/postgres.real.integration.test.ts` — line 440
- `tests/integration/db/real-driver/neo4j.real.integration.test.ts` — line 457

Remove the `.skip` and `npm run test:integration:db` reproduces the failure.

### Fix sketch
In each connector's `connect()`:
1. Wrap the driver's connect/pool-creation in a Promise.
2. On the driver's `error` event (or rejected internal promise), throw `new DbConnectorError(...)` with the documented code/phase/engine.
3. Preserve secret redaction in the error message (neo4j test asserts no password leakage).

### Acceptance
- 3 tests un-skipped and green against real testcontainers.
- A unit test per connector pinning the rejection shape on a stubbed driver.

### Affected files
- `src/db/connectors/mysql-connector.ts`
- `src/db/connectors/postgres-connector.ts`
- `src/db/connectors/neo4j-connector.ts`
- `src/db/errors.ts` (likely no change; just verify code constants exist)

## Issue 2: MySQL transaction-control statements fail under prepared-statement protocol (ER_UNSUPPORTED_PS)

### Summary
`MysqlConnector.beginTransaction()` / `commit()` / `rollback()` send `START TRANSACTION` / `COMMIT` / `ROLLBACK` via mysql2's `.execute()` (prepared-statement protocol), which the server rejects with `ER_UNSUPPORTED_PS` (error 1295). Two integration tests demonstrate the regression.

### Reproduction
Tests are skipped with TODO(v1.0.3) tags in:
- `tests/integration/db/real-driver/mysql.real.integration.test.ts` — line 457 (committed transaction)
- `tests/integration/db/real-driver/mysql.real.integration.test.ts` — line 490 (rolled-back transaction)

### Fix sketch
Route transaction-control statements through `connection.query()` (text protocol) instead of `connection.execute()` (prepared-statement). Either:
- a small allow-list of statements that must use `query()`, or
- a dedicated `executeTransactionControl(statement)` private method on `MysqlConnector`.

### Acceptance
- Both tests un-skipped and green.
- Unit test pins which API path is used for `START TRANSACTION` / `COMMIT` / `ROLLBACK`.

### Affected files
- `src/db/connectors/mysql-connector.ts`

## Issue 3: Neo4j integer property returns plain JS number instead of neo4j.Integer

### Summary
The driver's default in newer versions auto-coerces integers ≤ `Number.MAX_SAFE_INTEGER` to plain JS numbers, breaking the D4 contract ("pass driver objects through verbatim").

### Reproduction
Test skipped with TODO(v1.0.3) tag at `tests/integration/db/real-driver/neo4j.real.integration.test.ts:306`.

### Fix sketch
Two options:
1. Set `disableLosslessIntegers: false` explicitly on the driver config in `Neo4jConnector` so wrappers are always preserved.
2. Relax the D4 contract to allow JS numbers for safe-range integers and document the new behavior.

Option 1 is the consistent fix; option 2 changes the contract.

### Acceptance
- Test un-skipped and green.
- Decision documented in `docs/db-connector-contracts.md`.

### Affected files
- `src/db/connectors/neo4j-connector.ts`
- `docs/db-connector-contracts.md` (if option 2)
